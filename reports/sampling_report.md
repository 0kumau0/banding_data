## この文書について

クマ実データでの Adam-SGD は `sampling_rate = 1`
のまま回してきた。単回捕獲個体も
毎回すべて使っているので、**厳密には確率的勾配法になっていない**。実データは
1反復あたり約2200秒かかり試行錯誤ができないので、**合成データで
sampling_rate を 下げた場合に BFGS
解へ到達するかを先に確かめた**のがこの文書。

数値と図はすべて `results/` 以下の実測 CSV
から読んでいる。再生成はリポジトリルート
（`Claude/banding_data`）で次を実行してから knit する。

    Rscript examples/adcr_sgd_sampling.R gen
    Rscript examples/adcr_sgd_sampling.R run r100_const     # 以下 7 条件ぶん
    Rscript reports/render.R sampling_report

## 実装

`examples/adcr_sgd_sampling.R`。`gen` と `run` の2モードに分かれている。

**`gen` を分けてあるのは必須の作り。** `secrad_data$simulate()` は
`set.seed()` で 再現しない（C++ の `advdiff_t_core` が
`std::random_device` で独自に乱数を初期化する。 `tests/repro_check.R`
参照）。条件ごとにデータを作り直すと、比べているのが sampling_rate
の差なのかデータの差なのか分からなくなる。そこで **`gen` で 合成データと
BFGS 参照解を一度だけ作って `results/sampling_dataset.RData` に固定し、
全条件がそれを読む**。

目的関数の合成は既存実装（`SGD_bera_20260818.R`）と同じ:

``` r
sgd_loglik <- function(p, obj_multi, obj_single, n_detected, rate) {
  om <- obj_multi$loglf(p,  loglfscale = 1, sgd = TRUE)
  os <- obj_single$loglf(p, loglfscale = 1, sgd = TRUE)
  sum(dpois(n_detected, lambda = exp(om$lambda_grp), log = TRUE)) +
    om$loglfmulti + os$loglfmulti / rate
}
```

**複数回捕獲個体（`obj_multi`）は毎反復すべて使い、単回捕獲個体だけをサンプリングして
`1/rate` で重みを戻す。** これで全データ尤度の不偏推定になる。

実装上の要点が3つある。

- **1反復のミニバッチ内では同じ部分集合で有限差分を取る**（共通乱数）。
  `objfun` を反復の頭で1回だけ作り、`numDeriv::grad`
  の全評価がそれを使う。
  ここを評価ごとに引き直すと、差分の分子がサンプリングノイズに埋もれて勾配が壊れる
- **目的関数はミニバッチ値（`ll_batch`）と全データ値（`ll_full`）の両方を記録する。**
  ミニバッチ値だけ見ていると収束判定ができない。`ll_full` は高いので
  `EVAL_EVERY` 間隔で取る
- **学習率とステップ上限は係数ごとに持つ。**
  尤度曲面の曲率が係数によって違うため、
  スカラー1つでは片方が動かず片方が飛ぶ

### なぜサブサンプリングしても壊れないのか

**設計がそうなっていたから。**
単回捕獲個体は1個体あたりの情報量が小さい。
情報量の大きい複数回捕獲個体（88個体）は毎反復すべて使うので、
間引いている 166 個体は勾配の分散にあまり寄与しない。 既存の multi /
single 分割は、この意味で最初から正しかった。

ノイズ球（終盤50反復での係数のばらつき）は rate とともに素直に広がるが、
係数の値そのものより1桁以上小さいままで、増加分は連結性の共変量に集中している。

![図2. 終盤50反復での係数の標準偏差。sampling_rate
を下げるとノイズ球は広がるが、広がるのは主に連結性の共変量。](figures/samp-fig-noise-1.png)

## 結果2: ただし速度は買えない

**秒/iter が sampling_rate でほとんど変わらない。**

![図3. 1反復あたりの所要時間。バッチを 1/10 にしても 4.4%
しか速くならない。](figures/samp-fig-speed-1.png)

第1バッチ（5条件を同時に並列実行したので互いに比較できる）で **rate 1.0
の 12.90 秒/iter に対し rate 0.1 は 12.33 秒/iter。 バッチを 1/10 にして
4.4% しか速くならない。**

（第2バッチの2条件は並列度が違うので、秒/iter
をバッチを跨いで比べてはいけない。
上の図は第1バッチだけを使っている。第1バッチには rate 0.2
が2条件あるので 条件ごとに1本ずつ描いた。学習率スケジュールは `loglf`
の呼び出し回数を変えないので、 計算コストの比較としては const と decay
を並べてよい。）

理由は `loglf` のコスト構造にある。支配的な計算は `advdiff.eigen()`
が作る **ncell × ncell
行列**で、これは**個体数と無関係**。個体数に比例するのは
`logpcapthist`（ncell × nind）と pdot まわりだけ。

![図4. loglf のコストは個体数ではなくセル数で決まる。左: セル数を 900
に固定して個体数を変えた場合。右: advdiff
単体のセル数依存（両対数）。](figures/samp-fig-cost-1.png)

クマ実データは **ncell = 8497**。右の図から外挿すると advdiff
1回で約150秒、
1反復あたり約10回呼ばれるので約1500秒。残りが個体依存部分で、
観測されている **約2200秒/反復**とよく合う。

**速度は別の手当てが要る。** `obj_multi` と `obj_single`
が同じ格子・同じ `cpar` に対する advdiff
を別々に計算している（キャッシュ `self$adtemp`
がオブジェクトごとに独立）ので、 これを共有すれば約2倍。加えて
`numDeriv` の摂動順序を「連結性の係数を後ろにまとめる」
ように変えるとキャッシュミスが6回中5回から4回に減る。

## 結果3: 減衰と Polyak 平均は「到達してから」でないと害になる

定数学習率の Adam
は、理屈のうえでは最適点そのものではなくその周りのノイズ球に
留まる。そこで学習率減衰と Polyak
平均を試したが、**最初の設定では明確に悪化した。**

| 条件 | 減衰 tau | 平均開始 | 最大誤差(最終値) | 最大誤差(平均) | logL(最終値) | logL(平均) |
|:---|:---|:---|---:|---:|---:|---:|
| r020_const | なし | なし | 0.0317 | NA | -417.689 | NA |
| r020_decay | 50 | 100 | 0.2556 | 0.3876 | -429.591 | -451.834 |
| r020_polyak | なし | 150 | 0.0311 | 0.0385 | -417.724 | -417.705 |

![図5. 全データ対数尤度の推移（sampling_rate =
0.2）。減衰条件は到達前に失速している。](figures/samp-fig-loglik-1.png)

原因は手法ではなく**適用時期**だった。

- `decay_tau = 50` は iter 200 の時点で学習率を 1/5 まで落とす。
  **まだ最適点に到達していない過渡期に減速してしまい**、`ll_full` は
  iter 200 でも まだ改善中のまま打ち切られた
- `polyak_from = 100` は**接近途中の軌跡を平均**した。Polyak-Ruppert
  平均は 定常状態に入ってからでないと意味がない

定数学習率のまま
`polyak_from = 150`（到達後）に変えると、**平均のほうが最終反復値より
logL が良くなる**（-417.705 対 -417.724）。手法自体は正しく働く。

ただし係数の最大絶対誤差では平均のほうがわずかに悪い。**尤度が平坦な方向では、
係数の一致と尤度の一致は別物**であることに注意がいる。
そして今回は定数学習率でノイズ球が十分小さいので、**そもそも減衰は不要**だった。

    まで下げられる。既存実装のままで、追加の工夫は要らない。**

3.  **減衰と Polyak 平均を使うなら定常状態に入ってから。**
    過渡期に適用すると悪化する
