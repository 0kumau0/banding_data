# 2026-09-15 レポート — 失速の原因は `beta2` だった

09-14 に「クマの失敗を再現する検証台が無いので設定の比較ができない」と書いた。
その検証台を作り、比較を回した結果の記録。

## 要約

1. **検証台ができた。** クマ実データの失速が **5.2秒/反復** で再現する（実データは24分/反復）
2. **失速は再現する。** 別PC・別データでも同じ症状。データ固有の偶然ではない
3. **原因は `beta2 = 0.999` だった。** `beta2 = 0.99` ＋ `alpha × 4` で
   **BFGS 解に小数4桁まで一致**（距離/SE = 0.0012、logL 差 6.3×10⁻⁷）
4. **間引きは失敗の原因ではなかった。** 4つの `sampling_rate` が同じ場所に着く
5. **ただし間引きは速くもならなかった。** 実装上の理由（後述）
6. **`rate < 1` の対数尤度は条件間で比較できていなかった。** 修正済み

---

## 1. 検証台

`examples/sgd_simulation.R` を実データ版（`SGD_bera_20260818.R`）から移植し、
`examples/sgd_sim_conditions.R` で同じデータに複数条件を回せるようにした。

| | 検証台 A | 検証台 B |
|---|---|---|
| 目的 | **最適化器**の検証 | **間引き**の検証 |
| `TRUE_G0` / `TRUE_DENS` | −3.0 / −0.5 | −5.0 / 2.0 |
| 複数回 : 単回 | 約 40 : 60 | **18 : 170（1 : 9.4）** |
| 足環データとの対応 | — | **100 : 1000 の見込みに対応** |

**B が必要な理由**: この SGD は単回捕獲個体だけを間引く設計なので、
半々のデータでは `rate` を下げても実効個体数がほとんど減らず、**間引きを検証できない**。

### 同じデータに複数条件を回す必要がある

`set.seed` を固定しても検出パターンは再現しない（C++ 側が `std::random_device`
で独自に乱数を初期化するため）。**スクリプトを条件ごとに走らせると条件ごとに
別のデータになり、差が「設定のせい」か「データのせい」か分からなくなる。**
1回の実行の中で全条件を回すこと自体が、比較の前提になる。

## 3. 原因は `beta2` — 決着（検証台 A、`rate = 1.0` 固定）

| tag | `beta2` | `alpha` | 最大誤差 | logL 差 | 最大 距離/SE | 判定 |
|---|---|---|---|---|---|---|
| `base` | 0.999 | ×1 | 0.2937 | 1.09 | 1.258 | 未到達 |
| `b99` | 0.99 | ×1 | 0.2453 | 0.776 | 1.089 | 未到達 |
| `b90` | **0.9** | ×1 | 0.0012 | 7.4e−05 | **0.018** | ほぼ到達 |
| `b99_a2` | 0.99 | ×2 | 0.0194 | 5.2e−03 | 0.102 | ほぼ到達 |
| **`b99_a4`** | **0.99** | **×4** | **0.0003** | **6.3e−07** | **0.0012** | **到達** |

判定の目安: 距離/SE < 0.01 到達 / < 0.1 ほぼ到達 / < 1 標準誤差の範囲内 / ≥ 1 未到達

**`b99_a4` は BFGS 解と小数4桁まで一致した。**

```
                 dens_0   conn_0 conn_agri conn_wtr     g0_1
b99_a4         -0.14629 -0.81135   0.53054 -0.39126 -3.18798
BFGS（参照解） -0.14660 -0.81104   0.53050 -0.39125 -3.18769
```

### なぜ `beta2` なのか

Adam の歩幅は `alpha × m/√v`。`v` は勾配の2乗の指数移動平均で、
記憶の長さは約 `1/(1-beta2)` 反復。

| `beta2` | 記憶 |
|---|---|
| 0.999 | **約1000反復** |
| 0.99 | 約100反復 |
| 0.9 | 約10反復 |

実行は200反復。**`beta2 = 0.999` では序盤の大きな勾配（初回 130〜180）が
最後まで分母に残り、終盤の勾配（10前後）に対して歩幅を `alpha` の
1/20 以下に潰す。** 記憶を短くすれば分母が現在の勾配に追随する。

**この現象は文献にある。** Reddi, Kale & Kumar (2018) *ICLR* が
Adam の収束証明の誤りを指摘し、原因を `v` の指数移動平均に帰着させている。
引用先は `reports/references.md` を参照。

### 注意: `beta2 = 0.99` 単独では不十分

`b99`（0.99 / ×1）は **到達していない**（距離/SE = 1.089）。
`beta2` を下げるだけでは足りず、**`alpha` を上げて初めて届いた**。
09-10 の合成データ実験が「`beta2=0.99` ＋ `alpha×2.5` が最良」としていたのと整合する。

## 4. 間引き（検証台 B、`beta2 = 0.999` のとき）

| tag | rate | 使う個体 | 秒/反復 | 最大誤差 | 最大 距離/SE |
|---|---|---|---|---|---|
| `r100` | 1.00 | 188 | **5.74** | 0.989 | 5.28 |
| `r050` | 0.50 | 103 | 9.20 | 0.989 | 5.29 |
| `r020` | 0.20 | 52 | 10.92 | 0.991 | 5.21 |
| `r010` | 0.10 | 35 | 10.78 | 0.986 | 6.30 |

### ① 間引きは結果を変えなかった

```
       dens_0   conn_0 conn_agri conn_wtr     g0_1
r100  0.71625  0.13378   0.59622 -0.28227 -3.89655
r050  0.71594  0.13574   0.58994 -0.26414 -3.89655
r020  0.71427  0.14427   0.49586 -0.23437 -3.90044
r010  0.71884  0.12133   0.57491 -0.26796 -3.90258
```

**4条件が同じ場所に着いた。** 図でも `dens_0` / `conn_0` / `g0_1` は4本が完全に重なる。

**ただし `r100` 自体が到達していない**（距離/SE = 5.28）ので、
「間引いても大丈夫」とはまだ言えない。**全部が同じ壁に当たっているだけ。**
`beta2` を直した条件での再検証が要る（実行中）。

### ② 間引きのノイズは連結性の2係数にだけ乗る

図では `conn_agri` と `conn_wtr` だけが低い `rate` でギザギザに振れ、
`dens_0` / `conn_0` / `g0_1` は完全に重なる。

**理由は明確**: 密度の情報を運ぶポアソン項は `lambda_grp`（景観全体の量）から
計算され、**間引きの影響を受けない**。

> **予測を外した記録**: 09-15 に「単回個体は密度の情報を運ぶので、
> 間引きは `dens_0` を狙い撃ちで悪化させるはず」と書いたが**逆だった**。
> 影響を受けるのは空間共変量の係数のほう。

### ③ 間引いたら遅くなった ← 実装の問題

**個体を 1/5 にしたのに2倍近く遅い。** 前提が崩れている。

原因は `rate < 1` のとき毎反復 `create_subset_secrad()` で
**secrad オブジェクトを作り直している**こと（R6 オブジェクト2つ ＋
`set_model` の設計行列構築）。**この再構築コストが、個体を減らして
浮いたぶんを上回っている。**

- クマ実データ（`loglf` 1回178秒）なら再構築は無視できる
- **`ncell` が小さいと逆転する**

**対策**: 検出行列だけ差し替えて secrad オブジェクトを再利用する。未実装。

### ④ `rate < 1` の対数尤度は比較できていなかった

図の右下で4本が **−157 / −200 / −280 / −350** と大きくずれた。
しかし**係数はほぼ同一**なので、本当の尤度が違うはずがない。

`rate < 1` の `trace_ll` は間引いた推定値（`1/rate` 倍で重みを戻したもの）で、
分散が大きく系統的に低く出る。**係数が一致していて値だけずれる**ということは、
ずれが θ にほぼ依存しない定数で、**勾配には影響しない**（最適点は変わらない）。
4条件が同じ場所に着いたことと整合する。

**修正済み**: 各条件の終了時に**全データで対数尤度を1回測り直す**。
1回の評価なので費用は無視できる。
