## 0. 全体像 — このコードは何をしているのか

**3行でいうと:**

1. 架空の風景と架空の動物を作り、架空の調査をして「観測データ」をでっち上げる
2. そのデータから、動物の密度と「動きやすさ」を**2つの方法**で推定する
3. 2つの答えが一致するかを見る

```
  ┌─ §2 シミュレーション ────────────────────────┐
  │  真のパラメータ  →  動物を発生 → 動かす → 検出する  │
  │       （答えを知っている）            ↓          │
  └──────────────────────────── 観測データ ───┘
                                          │
                    ┌─────────────────┴──────────────┐
                    ↓                                 ↓
          §4 BFGS（確実だが重い）          §6 Adam-SGD（今回試したい方法）
                    ↓                                 ↓
                    └────────── §7 一致するか？ ──────┘
```

### なぜわざわざ偽のデータを使うのか

**本物のデータでは「正解」が分からないから。**

推定した値が 1.33 と出たとして、それが正しいのかどうかは本物のデータでは永久に
確かめられません。真の値を知っているのは神様だけです。

一方シミュレーションなら、**こちらが真の値を決めてからデータを作る**ので、
推定結果と答え合わせができます。「この方法はちゃんと動くのか」を確かめるには
これしかありません。

### なぜ「スケールダウン」なのか

本物のクマのデータはメッシュが 8,497 個あり、尤度の計算1回に約3分、
最適化を1歩進めるのに約24分かかります。試行錯誤ができません。

このコードは **400 個のメッシュ**（20×20）で同じことをします。
実装はまったく同じで、規模だけが小さい。**壊れているかどうかを数分で確かめられる**
ようにするのが目的です。

## 1. 前提知識

コードを読む前に、最低限の背景を4つ。

### 1.1 何を知りたいのか

**標識再捕獲法**（capture-recapture）という考え方が土台です。

湖に何匹の魚がいるか知りたいとします。全部数えるのは無理です。そこで

1. 100匹つかまえて印を付け、逃がす
2. しばらくしてまた100匹つかまえる
3. そのうち印つきが10匹だった → 印つきの割合は 10%
4. 最初に印を付けたのが100匹で、それが全体の10%なら、**全体は約1000匹**

これが基本の発想です。「何回つかまったか」のパターンから、
**つかまらなかった個体も含めた全体**を推定します。

### 1.2 ADCR は何を足したのか

古典的な方法は「動物は動かない」あるいは「動きは単純」と仮定します。
しかし実際の動物は、**通りやすい場所と通りにくい場所**を選んで動きます。
森は通れるが高速道路は渡れない、水域は避ける、といったことです。

ADCR（Advection-Diffusion Capture-Recapture）は、動物の動きを
**移流拡散方程式**という物理の式で表します。

| 用語 | 意味 | たとえ |
|---|---|---|
| **拡散**（diffusion） | ランダムに広がる動き | インクが水に広がる |
| **移流**（advection） | 一方向に流される動き | 川の流れに乗る |
| **連結性**（connectivity） | その場所の通りやすさ | 水の粘り気の逆 |

**この「連結性が場所によってどう違うか」を推定するのが ADCR の目玉**です。
連結性が高い ＝ 景観がつながっていて動物が行き来しやすい。
保全の現場では、どこが分断されているかを知ることが直接の関心事になります。

### 1.3 尤度と最尤推定

**尤度**（likelihood）とは「そのパラメータだったとして、実際に観測されたデータが
起きる確率」です。

コインで例えると、表が7回・裏が3回出たとします。

| 「表の出る確率 p」の候補 | この結果が起きる確率（＝尤度） |
|---|---|
| p = 0.3 | 0.009 |
| p = 0.5 | 0.117 |
| p = 0.7 | **0.267** ← 最大 |
| p = 0.9 | 0.057 |

**尤度がいちばん大きくなる p を答えとする**のが最尤推定（MLE）です。
この例では p = 0.7。「観測されたデータをいちばんうまく説明するパラメータ」を選ぶ、
という考え方です。

実際の計算では**対数尤度**（log-likelihood）を使います。確率は掛け算で増えるので
数が極端に小さくなり、桁が足りなくなるためです。対数を取れば掛け算が足し算になり、
安定して扱えます。コードに出てくる `logL = -685.52` のような値がそれです。
**大きい（0 に近い）ほど良い**当てはまりです。

### 1.4 推定する5つのパラメータ

| 名前 | 意味 | どこに効くか |
|---|---|---|
| `dens_0` | log(密度) | 動物が単位面積あたり何頭いるか |
| `conn_0` | log(連結性) の切片 | 景観全体の平均的な通りやすさ |
| `conn_agri` | 農地の効果 | 農地が多い場所は通りやすい/にくい |
| `conn_wtr` | 水域の効果 | 水域が多い場所は通りやすい/にくい |
| `g0_1` | log(検出率) | 検出器の真上にいる個体が捕まる確率 |

**すべて対数（log）スケール**です。密度も連結性も検出率も「マイナスにはなれない」
量なので、log を取って実数全体を動けるようにしています。
推定が `dens_0 = -1.45` なら、実際の密度は `exp(-1.45) = 0.235`。

連結性は場所ごとに変わるので、

```
log(その場所の連結性) = conn_0 + conn_agri × (その場所の農地率) + conn_wtr × (その場所の水域率)
```

という式で表します。これは**回帰式**そのもので、`conn_agri` が大きければ
「農地が多いほど通りやすい」という意味になります。

## 2. §0 設定ブロック — 触るのはここだけ

コードの最初の 130 行はすべて設定です。**実験で変えたくなる値を1か所に集めてある**
ので、下のコードは読まなくても実験ができます。

### 景観

```r
NX         <- 20        # メッシュは NX x NX セル（ncell = NX^2 = 400）
CELL_SIZE  <- 1         # セルの一辺
CELL_AREA  <- 1         # セルの面積
```

地図を 20×20 のマス目に切ります。**この `NX` がスケールダウンの主役**で、
計算コストはメッシュ数でほぼ決まります。本物のクマは 8,497 マスです。

### 調査デザイン

```r
TRAP_COORD <- c(3, 7, 11, 15, 18)
EFFORT     <- 200
```

`TRAP_COORD` は**片方の軸の座標**です。x と y の総当たりで 5 × 5 = **25基**の
検出器が格子状に並びます（この点は一度誤解を招いたので、コードに図を入れてあります）。

`EFFORT` は「どれだけがんばって調べたか」。カメラなら設置日数、
罠なら仕掛けた回数にあたります。**同じ場所でも努力が2倍なら検出数も2倍**になるので、
努力量を明示的に持たないと比較ができません。

### 真のパラメータ ← シミュレーションの心臓部

```r
TRUE_DENS  <- 0.0       # log 密度。exp(0) * 400セル ≒ 400 個体
TRUE_CONN  <- c(conn_0 = -1.0, conn_agri = 0.6, conn_wtr = -0.3)
TRUE_ADV   <- -0.5      # log 移流
TRUE_G0    <- -4.0      # log 検出率
```

**ここが「答え」です。** この値からデータを作るので、推定がこの値に近ければ
方法が正しく動いていることになります。

`TRUE_CONN` の読み方: 農地の係数が `+0.6`、水域が `-0.3`。
つまり**農地が多い場所ほど通りやすく、水域が多い場所ほど通りにくい**動物を
想定しています。絶対値が農地のほうが2倍大きいので、農地の効果のほうが強い。

`TRUE_G0 = -4.0` は `exp(-4) = 0.018`。検出器の真上にいても1回あたり2%弱しか
捕まりません。これに `EFFORT = 200` が掛かるので、そこそこ検出されます。

### 時間の刻み ← 落ちたらここを疑う

```r
STEPAD <- 100     # dt = TIMEBURNIN / STEPAD
```

動物の動きは微分方程式を**細かい時間刻みに切って順に進める**ことで計算します。
この刻み `dt` が粗すぎると計算が破綻し、確率がマイナスになって
`Negative probability produced` というエラーで止まります。

これは **CFL 条件**という、数値計算で有名な制約です。直感的には
「1ステップで動物が1マス以上動いてしまうと、計算が追いつかない」。
**落ちたら `STEPAD` を増やす**（＝刻みを細かくする）のが対処です。

### Adam の設定

```r
MAX_ITER <- 100
ALPHA    <- c(dens_0 = 0.02, conn_0 = 0.03, conn_agri = 0.03,
              conn_wtr = 0.03, g0_1 = 0.02)
MAX_STEP <- c(dens_0 = 0.05, conn_0 = 0.10, ...)
BETA1    <- 0.9
BETA2    <- 0.999
```

意味は §6 で説明します。ここでは「**係数ごとに別々の値を与えている**」ことだけ
押さえてください。パラメータによって尤度の曲面の形がまるで違うので、
共通の値ひとつでは片方が動かず片方が飛びます。

### 初期値

```r
INIT <- c(dens_0 = -1.0, conn_0 = -2.0, conn_agri = 0.0,
          conn_wtr = 0.0, g0_1 = -5.0)
```

**真の値からわざと離してあります。** 真値は `(0.0, -1.0, 0.6, -0.3, -4.0)` なので、
たとえば `g0_1` は −5 から −4 へ、`conn_0` は −2 から −1 へ動く必要があります。

**なぜわざと離すのか。** 本物の足環データでは、答えの見当がまったく付かない
状態から始めるしかありません。「良い初期値から始めればうまくいく」では
役に立たないので、**遠くから出発して届くか**を試しています。

### 設定の整合性チェック

```r
stopifnot(
  identical(names(ALPHA),    PAR_NAMES),
  ...
)
```

`ALPHA` などを名前付きベクトルで手書きしているので、**打ち間違いがあれば
ここで止まります**。名前がずれたまま走ると、間違った係数に間違った学習率が
当たって、原因の分からない挙動になります。数時間走らせてから気づくより、
最初の1秒で止まるほうがよい。

## 4. §2 シミュレーションデータの生成

**本物のデータ版では、ここが csv とシェープファイルの読み込みでした。**
それを「架空のデータを作る」に置き換えたのが、このスクリプトの本質です。

### 4.1 座標

```r
xcoord <- rep(seq_len(NX), each  = NX) * CELL_SIZE
ycoord <- rep(seq_len(NX), times = NX) * CELL_SIZE
```

400 マスそれぞれの中心座標を作ります。`each` と `times` の違いで
「x は 1,1,1,…,2,2,2,…」「y は 1,2,3,…,1,2,3,…」となり、
組にすると 20×20 の格子を過不足なく覆います。

### 4.2 環境共変量

```r
agri <- as.numeric(scale(sin(xcoord / 3) + cos(ycoord / 4)))
wtr  <- as.numeric(scale(cos(xcoord / 5) * sin(ycoord / 3)))
```

本物の「農地率」「水域率」に相当する値を、三角関数で**なめらかな起伏**として
作っています。隣り合うマスの値が似ている（＝空間的に相関がある）のが本物の
土地利用データの特徴なので、それを真似ています。

**`scale()` が重要です。** これは平均0・標準偏差1に変換する関数で、
**標準化**といいます。

なぜ必要か。農地率が 0〜1、水域率が 0〜0.05 のように**桁が違う**と、
係数の大きさを比べても意味がありません。「係数 0.36 と −6.41 では
後者のほうが影響が大きい」と読んでしまいますが、それは単位の違いを
見ているだけかもしれない。標準化しておけば、**係数がそのまま
「その変数が1標準偏差動いたときの効果」**になり、素直に比較できます。

> **実データ版はここを間違えていました。** `agri` に標準化を2回かけ、
> `wtr` は生のまま渡していました（2026-09-10 判明）。結果として
> 係数の大小関係の解釈が変わりました。詳細は `docs/20260910_作業記録.md`。

### 4.3 検出器の配置

```r
traps <- expand.grid(x = TRAP_COORD * CELL_SIZE,
                     y = TRAP_COORD * CELL_SIZE)
effort_loc <- match(paste(traps$x, traps$y), paste(xcoord, ycoord))
```

`expand.grid` が x と y の総当たり（25通り）を作ります。
`match` で「その座標は何番目のマスか」を引きます。
モデルは検出器を**マスの番号**で扱うので、座標から番号への変換が要ります。

### 4.4 データオブジェクトの組み立て

```r
simdata <- secrad_data$new(coords = ..., area = ..., grid_cov = ..., resolution = ...)
simdata$add_obs(type = "poisson", effort = ..., effort_loc = ..., effort_occ = ...)
```

`type = "poisson"` は**検出の数え方**の指定です。

| 型 | 意味 |
|---|---|
| `poisson` | 同じ個体が同じ検出器で**何回でも**検出されうる（回数を数える） |
| `bin` | 検出されたか否かの**0/1**だけ |

カメラトラップのように連続して撮れる状況は poisson が自然です。
**足環データでどちらが適切かは、まだ決まっていない論点**です（Step 4 の課題）。

### 4.5 真のモデルを与えて動かす

```r
simdata$set_truemodel(envmodel = list(D ~ 1, C ~ agri + wtr, A ~ 1), ...)
simdata$set_sim(EFFORT, STEPSPERTIME, STEPAD, TIMEBURNIN)
simdata$generate_ind()               # 真の個体を発生させる
simdata$simulate(verbose = FALSE)    # 移動と検出をシミュレート
simdata$update_detect()              # 1回以上検出された個体だけ残す
```

`envmodel` の `D ~ 1` などは R の**モデル式**です。

| 式 | 意味 |
|---|---|
| `D ~ 1` | 密度は場所によらず一定（切片だけ） |
| `C ~ agri + wtr` | 連結性は農地率と水域率で決まる |
| `A ~ 1` | 移流は一定 |
| `A ~ 0` | **移流を考えない**（推定側はこちら） |

3つの手順の意味:

- `generate_ind()` … 真の密度に従って個体をばらまく。**この時点では誰も検出されていない**
- `simulate()` … 個体を移流拡散で動かし、検出器の上を通ったら確率的に検出する
- `update_detect()` … **1回も検出されなかった個体を落とす**

最後が大事です。**現実の調査で手に入るのは「1回以上つかまった個体」だけ**です。
つかまらなかった個体は存在すら分かりません。その状況を再現しています。
そして「つかまらなかった個体が何頭いたか」を推定するのが、この手法の目的そのものです。

### 4.6 再現性についての重要な注意

```r
## ⚠ set.seed を固定しても検出パターンは毎回変わる。
```

**同じコードを2回走らせても、同じデータにはなりません。**

`secrad.r` の C++ 部分が `std::random_device` で独自に乱数を初期化しており、
R の `set.seed()` が効かないためです。個体のばらまきは R の乱数なので再現しますが、
**検出のパターンは毎回変わります**。

これが §7 で結果を保存する理由です。**走らせた結果は、残さなければ永久に失われます。**

### 4.7 複数回捕獲と単回捕獲に分ける

```r
capture_counts <- colSums(detect)    # 列 = 個体
multi_ids      <- which(capture_counts >  1)
single_ids     <- which(capture_counts == 1)
```

`detect` 行列は **行 = 検出器、列 = 個体**です。向きを間違えやすく、
行で切ると個体ではなく検出器を選んでしまいます（コードにも注意書きがあります）。

**なぜ2つに分けるのか。** 情報量が違うからです。

- **1回だけつかまった個体**: 「そこにいた」ことしか分からない
- **複数回つかまった個体**: つかまった場所どうしの関係から、**どれだけ動いたか**が分かる

連結性（動きやすさ）を推定したいのですから、**複数回個体のほうが圧倒的に貴重**です。
だから §5 で「複数回は毎回全部使い、単回だけ間引く」という設計にします。

## 5. §3 推定用オブジェクト

```r
MODEL <- list(envmodel = list(D ~ 1, C ~ agri + wtr, A ~ 0), ...)
secrad_obj <- secrad$new(secrdata = simdata)
secrad_obj$set_model(...)
```

**データを作ったときのモデル（`A ~ 1`）と、推定するモデル（`A ~ 0`）が違います。**
データには移流が入っているのに、推定側は移流がないものとして当てはめます。

これは意図的です。本物のクマの解析も `A ~ 0` で当てはめていました。
ただし結果として、**推定値は真値と完全には一致しません**。モデルが少し違うからです。
§7 で「比べる相手は真値ではなく BFGS 解」としているのは、これが理由の一つです。

```r
stopifnot(identical(names(generate_init(secrad_obj)), PAR_NAMES))
```

モデル式から自動的に決まる係数名が、設定ブロックで手書きした `PAR_NAMES` と
一致するかを確認しています。モデルを変えれば係数名も変わるので、
**設定ブロックを直し忘れたらここで止まります**。

## 6. §4 BFGS — 「確実なほうの答え」を先に出す

```r
secrad_res <- optim(INIT, secrad_obj$loglf, method = "BFGS",
                    control = list(maxit = OPTIM_MAXIT, trace = 1, REPORT = 10),
                    loglfscale = -1, hessian = RUN_HESSIAN)
```

### `optim` とは

R の標準の最適化関数です。「この関数を**最小**にするパラメータを探して」と頼みます。

### `loglfscale = -1` の意味

私たちは対数尤度を**最大化**したい。`optim` は**最小化**しかしない。
そこで符号を反転させて渡します。**マイナスをかけて最小化 ＝ 最大化**です。
`-secrad_res$value` で符号を戻して表示しているのはこのためです。

### BFGS とは

**準ニュートン法**と呼ばれる手法です。直感的には:

- ただの勾配法は「今いる地点の傾き」だけを見て進む
- BFGS は進みながら「**地形の曲がり具合**」を推定し、それを使って賢く進む

谷が細長く曲がっているとき、傾きだけ見て進むとジグザグして進みません。
曲がり具合が分かっていれば、谷に沿ってまっすぐ進めます。

**代償は1歩あたりのコスト**です。BFGS は微分（勾配）を必要とし、
式で微分できないので**数値微分**します。パラメータが5つなら1歩に
6回以上の尤度計算が要ります。1回3分なら1歩で20分。
**本物の足環データではこれが重すぎて落ちる**、というのが SGD を採る理由です。

### ヘッセ行列と標準誤差

```r
se <- sqrt(diag(solve(secrad_res$hessian)))
```

**ヘッセ行列**は「曲がり具合」を表す行列です。最適点の周りで尤度が
**尖っていれば**そのパラメータは精度よく決まっており、
**平たければ**あまり決まっていない。

その逆行列の対角成分の平方根が**標準誤差**、つまり推定値のばらつきの目安です。
「1.33 ± 0.12」の「± 0.12」にあたります。これがないと、
推定値が意味のある差なのかノイズなのか判断できません。

## 7. §5 SGD の部品

ここからが本題の Adam-SGD です。

### 7.1 個体を絞ったオブジェクトを作る

```r
create_subset_secrad <- function(secrdata, ids) {
  ...
  detect = as.matrix(o$detect[, ids, drop = FALSE])
  ...
}
```

指定した個体だけを持つ新しいオブジェクトを作ります。
**`[, ids]` と列で切る**のがポイント（行で切ると検出器を選んでしまう）。

`drop = FALSE` は R の癖への対処です。1個体だけ選ぶと R は行列を
勝手にベクトルに変換してしまい、後の処理が壊れます。それを止めています。

### 7.2 SGD の目的関数

```r
sgd_loglf <- function(par, obj_multi, obj_single, n_detected, sampling_rate) {
  out_multi  <- obj_multi$loglf(par,  loglfscale = 1, sgd = TRUE)
  out_single <- obj_single$loglf(par, loglfscale = 1, sgd = TRUE)

  ll_pois <- sum(dpois(n_detected, lambda = exp(out_multi$lambda_grp), log = TRUE))
  ll_hist <- out_multi$loglfmulti + out_single$loglfmulti / sampling_rate

  ll_pois + ll_hist
}
```

ADCR の対数尤度は**2つの部分の和**です。

| 部分 | 意味 |
|---|---|
| `ll_pois` | **何頭検出されたか**の確率（ポアソン分布） |
| `ll_hist` | **各個体がどんなパターンで検出されたか**の確率 |

前者が「全体で何頭いるか」の情報を、後者が「どれだけ動くか」の情報を担います。

**`sgd = TRUE` の意味**: 通常 `loglf` は合計したスカラーを返しますが、
`sgd = TRUE` にすると**合計する前の部品**を返します。
部品で受け取れば、単回捕獲のぶんだけ `/ sampling_rate` で重みを戻す、
という細工が外側でできます。

**`/ sampling_rate` の意味**: 単回捕獲個体を 10% だけ使ったなら、
その寄与は本来の 1/10 しかありません。10倍して全体を推定します。
標本調査で「抽出率の逆数を掛けて母集団を推定する」のと同じ発想です。

### 7.3 advdiff キャッシュの共有

```r
obj_multi <- create_subset_secrad(simdata, multi_ids)
adcache   <- share_advdiff_cache(list(obj_multi))

if (is_full_sampling) {
  obj_single_fixed <- create_subset_secrad(simdata, single_ids)
  share_advdiff_cache(list(obj_single_fixed), cache = adcache)
}
```

**これがこのコードで一番分かりにくい部分**なので、丁寧に説明します。

#### 何が重いのか

ADCR では「行動圏の中心がマス *i* にある個体は、空間のどこにいるか」という
確率分布を、マスの数だけ計算します。**400マスなら 400×400 の行列**、
クマの 8,497 マスなら 8,497×8,497 の行列（**578 MB、1回 約150秒**）です。
尤度計算のコストのほとんどがここです。

#### 重要な性質

**この計算は「地形」と「連結性・移流のパラメータ」だけで決まります。
どの個体を持っているかには一切依存しません。**

#### 何が無駄だったか

目的関数は `loglf` を2回呼びます（複数回個体用と単回個体用）。
2つは別々のオブジェクトで、**それぞれが自分のキャッシュを持っています**。

```
obj_multi  : 同じパラメータで advdiff を計算 → 自分のキャッシュに保存
obj_single : 自分のキャッシュは空 → まったく同じ計算をもう一度
```

**持っている個体が違うだけで、結果は完全に同じなのに、2回計算していました。**

#### 対処

`share_advdiff_cache` は**両方に同じキャッシュを指させます**。
片方が計算した結果を、もう片方がそのまま使えます。
地形が違うオブジェクト同士を繋ごうとすると、関数が止めてくれます。

#### 評価順序との組み合わせ

勾配は数値微分なので、1回の反復で **基準1回 + 係数5つの摂動5回 = 6回**の
尤度計算が要ります。このうち **advdiff を変えるのは `conn_*` の3つだけ**で、
`dens_0` と `g0_1` は変えません。

##### 前提: キャッシュは1件しか持たない

```r
e$adpar <- NA   # 直前の cpar
e$adout <- NA   # そのときの advdiff の結果
```

**過去の結果を溜める辞書ではなく、直前の1件だけを置く棚です。**
ここが効いてきます。新しい `cpar` で計算すると、前の結果は**上書きされて消えます**。

##### 改善前 — 6回中5回が外れる

| # | 揺らす係数 | `cpar` | 棚の状態 |
|---|---|---|---|
| 1 | （基準） | `c0` | ミス → 計算し `c0` を置く |
| 2 | `dens_0` | `c0` | **ヒット**（直前が `c0` なので偶然当たる） |
| 3 | `conn_0` | `c1` | ミス → `c1` で上書き |
| 4 | `conn_agri` | `c2` | ミス → `c2` で上書き |
| 5 | `conn_wtr` | `c3` | ミス → `c3` で上書き |
| 6 | `g0_1` | `c0` | **ミス** ← 棚は `c3`。`c0` は追い出されている |

**ミスは6回中5回。** これが複数回個体と単回個体で各1回ずつ走るので **5 × 2 = 10回**です。

`dens_0` だけは基準の直後にあるので偶然ヒットしていました。6回とも外していれば
12回だったはずで、**10 という数字はこの偶然のヒットから来ています**。

##### 改善後 — 同じ `cpar` をまとめる

| # | 揺らす係数 | `cpar` | 棚の状態 |
|---|---|---|---|
| 1 | （基準） | `c0` | **計算 ①** |
| 2 | `dens_0` | `c0` | ヒット |
| 3 | `g0_1` | `c0` | ヒット ← 前に持ってきたので当たる |
| 4 | `conn_0` | `c1` | **計算 ②** |
| 5 | `conn_agri` | `c2` | **計算 ③** |
| 6 | `conn_wtr` | `c3` | **計算 ④** |

そして①〜④のそれぞれを、**複数回個体と単回個体で使い回します**。合計 **4回**。

##### 2つの対策は独立している

| | 1反復あたりの advdiff |
|---|---|
| 何もしない | **10回** |
| キャッシュ共有だけ | 5回 |
| 共有 ＋ 順序の並べ替え | **4回** |

- **共有**が 10 → 5（複数回個体と単回個体の二重計算をなくす）
- **順序**が 5 → 4（最後に `c0` へ戻る余分なミスをなくす）

**もしキャッシュが `cpar` をキーにした辞書だったら、どんな順序でも自然に4回になり、
並べ替えは不要でした。** 1件しか置けない棚を前提に、同じ `cpar` を使う評価を
連続させているのが `grad_cachewise` のやっていることです。

実測で **1.57倍**（`tests/cache_bench.R`）。メモリも半分になります。
**勾配の値は1ビットも変わりません**（最大差 0 を確認済み）。
評価の順序を変えて、同じ計算を使い回しているだけです。

#### 間引くときの注意

```r
get_single_obj <- function(ids) {
  if (is_full_sampling) return(obj_single_fixed)
  obj <- create_subset_secrad(simdata, ids)
  share_advdiff_cache(list(obj), cache = adcache)   # 作り直すたびに繋ぎ直す
  obj
}
```

`SAMPLING_RATE < 1` だと単回個体のオブジェクトを**毎回作り直す**ので、
そのつどキャッシュに繋ぎ直す必要があります。忘れるとそこだけ余分に計算が走ります。

## 8. §6 Adam-SGD 本体

### 8.1 勾配とは

**勾配**（gradient）は「各パラメータを少し動かしたら、対数尤度がどれだけ変わるか」
を並べたベクトルです。山登りでいう**傾き**で、その方向へ進めば尤度が上がります。

ADCR の尤度は式で微分できないので、**数値微分**します。

```r
g <- grad_cachewise(func = objfun, x = current_par, eps = GRAD_EPS)
```

やっていることは素朴です。**各パラメータをほんの少し（`GRAD_EPS = 1e-4`）動かして、
尤度がどれだけ変わったかを差で割る**。これが**前進差分**です。

```
勾配 ≈ ( f(x + eps) - f(x) ) / eps
```

### 8.2 ミニバッチ

```r
ids <- if (is_full_sampling) single_ids
       else sample(single_ids, size = min(sample_size, length(single_ids)))
```

**SGD（確率的勾配降下法）**の「確率的」はここです。
毎回すべてのデータを使うのではなく、**一部だけ抽出して勾配を計算**します。

1歩あたりのコストが下がるかわりに勾配にノイズが乗りますが、
歩数を稼げるので全体として速くなる、というのが狙いです。
機械学習で標準的に使われる考え方です。

このコードでは**複数回捕獲個体は毎回全部使い、単回捕獲だけを抽出**します。
貴重な情報を捨てないための設計です。`SAMPLING_RATE = 1.0` なら間引かず、
普通の勾配法になります。

### 8.3 Adam の更新式

```r
m <- BETA1 * m + (1 - BETA1) * g
v <- BETA2 * v + (1 - BETA2) * g^2
m_hat <- m / (1 - BETA1^iter)
v_hat <- v / (1 - BETA2^iter)

step <- ALPHA * m_hat / (sqrt(v_hat) + EPS_ADAM)
step <- pmax(pmin(step, MAX_STEP), -MAX_STEP)

current_par <- current_par + step
```

**Adam** は「どれだけ進むか」を自動調整する手法です。1行ずつ見ます。

#### `m` — 勾配の平均（1次モーメント）

```r
m <- BETA1 * m + (1 - BETA1) * g
```

過去の勾配を `BETA1 = 0.9` の重みで覚えつつ、新しい勾配を 10% 混ぜます。
**指数移動平均**で、ノイズをならす働きをします。
ミニバッチの勾配はガタガタするので、平均して安定させます。

#### `v` — 勾配の2乗の平均（2次モーメント）

```r
v <- BETA2 * v + (1 - BETA2) * g^2
```

勾配の**大きさ**の記録です。`BETA2 = 0.999` なので、
**およそ 1/(1−0.999) = 1000 反復ぶんの記憶**を持ちます。

#### バイアス補正

```r
m_hat <- m / (1 - BETA1^iter)
v_hat <- v / (1 - BETA2^iter)
```

`m` と `v` は 0 から始まるので、最初のうちは本来より小さく出ます。
それを割り算で補正しています。反復が進めば `BETA^iter` は 0 に近づき、
補正は効かなくなります。

#### 歩幅

```r
step <- ALPHA * m_hat / (sqrt(v_hat) + EPS_ADAM)
```

**Adam の核心**です。勾配の平均を、勾配の大きさで**割ります**。

- 勾配がずっと大きい方向 → 分母も大きい → 歩幅は抑えられる
- 勾配が小さい方向 → 分母も小さい → 歩幅は確保される

つまり**パラメータごとに自動で歩幅が調整**されます。
`m/sqrt(v)` はおおむね ±1 の範囲に収まるので、**実際の歩幅はほぼ `ALPHA`**
になります。だから `ALPHA` は「1歩でどれだけ動くか」とほぼ読めます。

`EPS_ADAM = 1e-8` はゼロ割り防止です。

> **この `m/sqrt(v)` の比は診断に使えます。** 1 に近ければ設計どおりの歩幅、
> 極端に小さければ何かが起きている。2026-09-14 の調査ではこれを見ました
> （ただし**小さいこと自体は異常ではありません**。収束して勾配が0に近づけば
> 当然小さくなります。詳細は `reports/20260914_report.md`）。

#### 歩幅の上限

```r
step <- pmax(pmin(step, MAX_STEP), -MAX_STEP)
```

**発散の歯止め**です。何かの拍子に巨大な一歩を踏んで計算が壊れるのを防ぎます。
実データの実行では**一度も発動しませんでした**。保険です。

### 8.4 記録

```r
trace_par[iter, ]  <- current_par
trace_grad[iter, ] <- g
trace_step[iter, ] <- step
trace_ll[iter]     <- objfun(current_par)
```

毎回の値をすべて残します。**画面に出る情報だけでは後から診断できません。**
「勾配は正しい方を向いていたか」「歩幅はいつから小さくなったか」は、
この記録を後で解析して初めて分かります。実際、2026-09-14 の診断はすべて
この4つの行列を読んで行いました。

## 9. §7 比較と保存

### 9.1 3段の比較表

```r
cmp <- rbind(`真値` = ..., `Adam-SGD` = ..., `BFGS（参照解）` = ..., `差` = ...)
```

**比べる相手が2つあり、意味が違います。**

| 比較 | 何が分かるか |
|---|---|
| SGD ↔ **BFGS** | **最適化がうまくいったか**。同じ尤度を別の方法で最大化しているので、**一致すべき** |
| SGD ↔ **真値** | **推定量の性能**。データが有限である以上、ぴったりにはならない |

**最適化の成否を判定するのは前者です。** 真値とのずれは、
データの量やモデルの近似から来るもので、最適化の失敗ではありません。
コードにもその旨を出力しています。

```r
cat("＊ 比べる相手は真値ではなく BFGS 解。\n")
```

### 9.2 なぜ保存するのか

```r
save(secrad_res, ref_par, true_par, final_par,
     trace_par, trace_ll, trace_grad, trace_step, ...,
     file = RESULTFILE)
```

理由は2つ。

1. **診断スクリプトがこの trace を読む**（`examples/diagnose_far_runs.R` など）
2. **この実行は再現できない**（§4.6）。`set.seed` が効かないので、
   走らせ直しても同じデータにはなりません。**残さなければ永久に失われます**

なお `.gitignore` に `*.RData` があるため、**このファイルは git に乗りません**。
別PCへ渡すには手で渡すか、gitignore に例外を足す必要があります。

## 10. つまずきやすい点

| 点 | 中身 |
|---|---|
| **`detect` の向き** | 行 = 検出器、列 = 個体。個体で絞るのは**列** |
| **再現性がない** | `set.seed` を固定しても検出パターンは毎回変わる |
| **`TRAP_COORD` は片軸** | n 個指定すると n² 基になる |
| **`loglfscale = -1`** | 最大化したいので符号を反転して `optim` に渡す |
| **真値と一致しなくてよい** | 判定基準は BFGS 解との一致 |
| **生成モデルと推定モデルが違う** | データには移流があるが推定は `A ~ 0` |
| **CFL 条件** | `STEPAD` が小さいと `Negative probability produced` で落ちる |
| **標準化を忘れない** | 係数の大小関係の解釈が変わる |

## 11. 用語集

| 用語 | 意味 |
|---|---|
| **尤度** | そのパラメータだとして、観測データが起きる確率 |
| **対数尤度** | 尤度の対数。掛け算が足し算になり数値的に安定する。大きいほど当てはまりが良い |
| **最尤推定（MLE）** | 対数尤度を最大にするパラメータを答えとする方法 |
| **勾配** | 各パラメータを動かしたときの対数尤度の変化率。山の傾き |
| **数値微分／前進差分** | 式で微分できないとき、少し動かして差を取る方法 |
| **ヘッセ行列** | 曲がり具合を表す行列。逆行列から標準誤差が出る |
| **標準誤差** | 推定値のばらつきの目安 |
| **BFGS** | 曲がり具合を推定しながら進む最適化手法。確実だが1歩が重い |
| **SGD** | データの一部だけで勾配を計算し、歩数を稼ぐ手法 |
| **Adam** | パラメータごとに歩幅を自動調整する SGD の一種 |
| **ミニバッチ** | 1歩の勾配計算に使うデータの部分集合 |
| **学習率（`ALPHA`）** | 1歩でどれだけ動くかの基本量 |
| **移流** | 一方向に流される動き |
| **拡散** | ランダムに広がる動き |
| **連結性** | 景観の通りやすさ。ADCR が推定したい主対象 |
| **標準化** | 平均0・標準偏差1に変換すること。係数を比較可能にする |
| **CFL 条件** | 時間刻みが粗すぎると数値計算が破綻するという制約 |
