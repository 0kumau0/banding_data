# 使える設定の窓を測る — 挟み撃ちの結果

**この1本で 2026-09-16 の実験は追える。** 経緯は `docs/20260916_作業記録.md`、
現在の状態は `docs/20260916_引継ぎ.md`。

---

## 0. 結論（先に）

1. **`beta2` を短くすれば、`alpha` は何でもよい。** `beta2 = 0.9` なら
   `alpha` を ×1 から ×8 まで振っても**全部 BFGS 解に到達する**
2. **窓の中央は `beta2 = 0.9` / `alpha` ×1〜×2**
3. **上端は「壊れる」形では現れなかった。** ×8 でも発散も NaN も無く、
   **最終精度が単調に緩む**形で現れる（誤差 0.0021 → 0.0187、9倍）
4. **下端は見えた。** `beta2 = 0.5` で悪化（logL 差が他の 30〜500倍）
5. **`alpha` は「いつ着くか」、`beta2` は「着くかどうか」を決める。**
   役割が違う。クマの2条件立て（×1 と ×2）はこれで裏が取れた
6. **間引きは着地点を変えない。** `rate` 1.0 → 0.1（個体 201 → 36）で
   対数尤度の差は 0.17 以内（§8）
7. **⚠ BFGS 参照解が最大点でない場合がある。** 09-17 の実行で
   **Adam 5条件すべてが BFGS より 2.16 対数尤度ぶん高い点に着いた。**
   再出発で実証済み。**判定規則を改める必要がある**（§8）

## 2. 実験② — 反復数ではなく設定だった

検出 211（複数回 15 / 単回 196）、BFGS logL −86.3193。

| `beta2` | `alpha` | 全データ logL 差 | 終盤の判定 |
|---|---|---|---|
| 0.999 | ×1 | 8.05 | 失速 |
| 0.99 | ×1 | 5.58 | 失速 |
| **0.9** | **×1** | **0.19** | 一方向に進行中 |
| 0.99 | ×2 | 3.46 | 失速 |
| 0.99 | ×4 | 3.00 | 失速（`\|step\|` は `alpha` の 1/33） |

**400反復あっても `beta2 = 0.999` は 8.05 遅れたまま。`0.9` は 0.19。
同じデータ・同じ反復数で40倍の差**なので、反復数の問題ではない。

**`alpha` を4倍にしても救えない。** 歩幅を増やしても分母がそれ以上に潰す。
図では `b90` だけが 230反復あたりで平坦部を脱出する。

### 訂正: 「距離/SE」は失速点では当てにならない

| | `b90` | `b99_a4` |
|---|---|---|
| 距離/SE | 0.947（悪い） | **0.245（良い）** |
| 全データ logL 差 | **0.19（良い）** | 3.00（悪い） |

**指標が失速した条件を最良と判定した。** `H⁻¹g` の `H` を参照解の位置で評価しているため、
離れた場所では2次近似が当てにならない。

**以後、判定は全データ logL 差を主、距離/SE を従とする。**
距離/SE が意味を持つのは既に近くにいるときだけ。**クマ実データの判定でも同じ扱いにすること。**

## 3. 実験③ — 窓を測る（挟み撃ち）

```
--testbed B --max-iter 400 \
--conditions "b90_a1:0.9:1,b90_a2:0.9:2,b90_a4:0.9:4,b90_a8:0.9:8,b80_a4:0.8:4,b50_a4:0.5:4"
```

検出 201（複数回 15 / 単回 186 ＝ 1 : 12.4）、BFGS logL −87.5484。
記憶を固定して歩幅を振る4本 ＋ 歩幅を固定して記憶を振る2本の十字。

| tag | `beta2` | `alpha` | 最大誤差 | logL 差 | 最大 距離/SE | 判定 |
|---|---|---|---|---|---|---|
| **`b90_a1`** | 0.9 | ×1 | **0.00215** | **0.00023** | **0.0023** | **到達（最良）** |
| `b90_a2` | 0.9 | ×2 | 0.00429 | 0.00043 | 0.0052 | 到達 |
| `b90_a4` | 0.9 | ×4 | 0.00659 | 0.00420 | 0.0170 | ほぼ到達 |
| `b90_a8` | 0.9 | ×8 | 0.01873 | 0.01919 | 0.0503 | ほぼ到達 |
| `b80_a4` | 0.8 | ×4 | 0.00610 | 0.00146 | 0.0349 | ほぼ到達 |
| `b50_a4` | **0.5** | ×4 | **0.02680** | **0.11768** | 0.0573 | ほぼ到達（**最悪**） |

**6条件すべてが到達した。** 実験②で `beta2 = 0.999 / 0.99` が軒並み失速したのと対照的で、
**`beta2` さえ短ければ、あとは何でも着く**ことが分かる。

### 3.1 窓の上端 — 「壊れる」形では現れなかった

**予想は外れた。** `alpha` ×8 で振動・発散・NaN を見込んでいたが、**どれも起きない。**
代わりに**最終精度が単調に緩む**:

```
×1 → ×2 → ×4 → ×8
0.0021  0.0043  0.0066  0.0187      （最大誤差。9倍に悪化）
```

図では `b90_a8`（紫）が序盤に最も大きく行き過ぎ、最後まで細かく振動している。
**Adam の歩幅は `alpha` に正規化されるので、`alpha` は「最適点のまわりを回る輪の大きさ」を決める。**
輪が大きいほど着地点が緩む。**発散しないのは歩幅が勾配の大きさに依らないから**で、
これは Adam の設計どおりの挙動。

**実用上の上端は ×2。** ×4 以上は精度と引き換えに何も得ていない（下の 3.3 参照）。

### 3.2 窓の下端 — こちらは見えた

`alpha` ×4 で固定して記憶だけを振ると:

| `beta2` | 記憶 | 最大誤差 | logL 差 |
|---|---|---|---|
| 0.9 | 約10反復 | 0.00659 | 0.00420 |
| 0.8 | 約5反復 | 0.00610 | 0.00146 |
| **0.5** | **約2反復** | **0.02680** | **0.11768** |

**0.9 と 0.8 は同等。0.5 で明確に悪化**（logL 差は他条件の 30〜500倍）。
図でも `b50_a4`（灰）だけが終始ギザギザで、収束後も振れ幅が残る。

**記憶が2反復では、分母が1回ごとの勾配のばらつきをそのまま拾う。**
`√v` が本来の役割（大きさの安定した推定）を果たせなくなっている。

> **注意**: これは `rate = 1.0`（完全バッチ）での結果。
> **勾配に標本のばらつきが乗る `rate < 1` では、下端はもっと上がるはず。**
> 足環データは間引いて回すので、**この下端は実験②の続き（段2）で測り直す必要がある。**

### 3.3 窓のまとめ

| | 値 | 根拠 |
|---|---|---|
| **上端（歩幅）** | `alpha` **×2** | ×4 以上は精度が緩むだけ。到達の早さは ×2 で足りる |
| **下端（記憶）** | `beta2` **0.8** | 0.5 で明確に悪化。0.8 と 0.9 は同等 |
| **中央** | **`beta2` = 0.9 / `alpha` ×1〜×2** | 誤差最小（0.0021 / 0.0043） |

**足環データへ持ち込むのはこの3行。**

## 4. `alpha` と `beta2` は役割が違う

**この日いちばんの収穫。**

| | 決めるもの |
|---|---|
| **`beta2`** | **着くかどうか**（記憶が長いと分母が居座り、永久に着かない） |
| **`alpha`** | **いつ着くか、どれだけ細かく着くか**（着地の輪の大きさ） |

`b90_a1` の到達時期を trace で見ると:

| 反復 | 全データ logL | 判定 |
|---|---|---|
| 100 | −102.59 | 一方向に進行中 |
| **200** | **−87.628**（BFGS との差 0.079） | まだ進行中 |
| 約250 | −87.549 | **振動 ＝ 到達** |

**`alpha` ×1 は 250反復ほどかかる。** `alpha` を上げれば早く着くが、着地は緩くなる。

### クマ実データへの含意

| 条件 | 向き |
|---|---|
| **`b90`（×1）** | 300反復以上回せるなら**最も精密** |
| **`b90a2`（×2）** | **200反復で切り上げるなら安全**。早く着く |

**この2条件立ては冗長ではなく補完だった。** 1反復24分・200反復で3.3日という制約下では、
どちらが当たるかが事前に決められない。**両方走らせる判断は正しい。**

## 5. 副次的な観察

### 5.1 秒/反復の比較は過信しない

この実行の秒/反復は 5.4 / 5.4 / 8.2 / 10.7 / 10.8 / 10.8 で、
**後半3条件がすべて 10.75 前後で同一**。条件による計算量の差では説明できない
（`rate = 1.0` 固定なので使う個体数は全条件同じ）。
**マシン側の要因**（サーマルスロットリング等）を疑うべき値。

**「間引くと遅くなる」の観察（実験①）も、この不確かさを込みで読むこと。**
再測するなら条件の順序を入れ替えて確かめる。

### 5.2 データによって難しさが大きく違う

| 実行 | 検出 | 複数回 | BFGS の `conn_0` | `conn_0` の SE |
|---|---|---|---|---|
| 実験② | 211 | 15 | **−7.79** | **3.74** |
| 実験③ | 201 | 15 | −1.10 | 0.63 |

**同じ設定で生成しても、引いたデータで参照解が桁違いに変わる。**
実験②のデータは尤度面が極端に平たく、BFGS 解自体が尾根の端に乗っていた。
**最適化の目標としては正しいが、推定値として読んではいけない。**

`set.seed` が効かないので**この違いは制御できない**。
**だからこそ条件比較は1回の実行の中で回す**（データを共有する）必要がある。

## 6. 実験④（追記 2026-09-17）— 検証台A での裏取り

検出 92（複数回 39 / 単回 53 ＝ 1 : 1.4）。**クマ実データ（1 : 0.85）に近い構成。**

| tag | `beta2` | `alpha` | 最大誤差 | logL 差 | 最大 距離/SE |
|---|---|---|---|---|---|
| `b90_a1` | 0.9 | ×1 | 0.00116 | 1.09e−04 | 0.0069 |
| `b90_a2` | 0.9 | ×2 | 0.00285 | 1.08e−03 | 0.0113 |
| `b99_a4` | 0.99 | ×4 | 0.000109 | 3.78e−07 | 2.6e−08 |

**クマの2条件は検証台Aでも通る。変更する理由は無い**（目的は達成）。

**ただし検証台Aには設定を選ぶ力が無い。** 3条件とも到達し、
**差は標準誤差（0.15〜0.23）の 1/100 以下**。実務上は区別が付かない。

**表の上では `b99_a4` が1桁良いが、これを採ってはいけない**:

- 差が標準誤差の 1/100 以下で、意味のある差ではない
- **`b99_a4` は検証台B で失速した**（§2、logL 差 3.00）。**`b90` は A でも B でも通る**
- クマ実データは検証台Aよりはるかに難しい（`ncell` 8497、実共変量、週末実行は実際に失速）。
  **易しい問題で全条件が通ったことは、難しい問題での優劣を何も保証しない**

**頑健性で選ぶ。クマは `b90` / `b90a2` のまま。**

> 09-14 に「合成データは設定の比較に使えない（全条件が収束するので優劣を判定する力がない）」
> と書いた現象が、検証台Aで再現している。**検証台Aは「通るか」は言えるが「どれが良いか」は言えない。**
> **窓を測る役は検証台B が担う。**

### 秒/反復の疑いが強まった

検証台A は個体数92（B は201）で `ncell` は同じ。**B より速いはずが 9.9〜10.0 秒**で、
B の `b90_a1`（5.8秒）より遅い。しかも3条件がほぼ同一値。
**§5.1 の疑い（マシン側の要因）を裏づける。秒/反復による条件間の比較は当面すべて保留。**

## 8. 実験⑤（追記 2026-09-17）— 間引きの検証と、参照解の失敗

```
--testbed B --max-iter 400 \
--conditions "r100:0.9:1:1.0,r050:0.9:1:0.5,r020:0.9:1:0.2,r010:0.9:1:0.1,s010:0.8:1:0.1"
```

検出 201（複数回 18 / 単回 183 ＝ 1 : 10.2）。

| tag | `beta2` | `rate` | 使う個体 | 全データ logL | **参照解との差** |
|---|---|---|---|---|---|
| `r100` | 0.9 | 1.00 | 201 | **−91.1534** | **+2.160** |
| `r010` | 0.9 | 0.10 | 36 | −91.1648 | +2.149 |
| `r050` | 0.9 | 0.50 | 109 | −91.1763 | +2.137 |
| `s010` | 0.8 | 0.10 | 36 | −91.2133 | +2.100 |
| `r020` | 0.9 | 0.20 | 54 | −91.3228 | +1.991 |
| **BFGS（参照解）** | | | 201 | **−93.3137** | 0 |

**差の符号が逆である。5条件すべてが参照解より上にいる。**

### 8.1 BFGS のほうが失敗していた

| | `dens_0` | `conn_0` | `conn_agri` | `conn_wtr` | `g0_1` |
|---|---|---|---|---|---|
| 真値 | 2.000 | −1.000 | 0.600 | −0.500 | −5.000 |
| Adam 5条件 | 2.28〜2.34 | −0.55〜−0.67 | 1.03〜1.13 | −0.61〜−0.70 | −5.43〜−5.49 |
| BFGS | 2.729 | **+0.847** | **9.257** | −0.773 | −5.860 |

**BFGS は `conn_agri = 9.26`（真値 0.6）へ走り去り、20反復で `convergence = 0` を返した。**
平坦な尾根に沿って滑り出たまま停まった形。標準誤差 1.69 もその位置の異常を示している。

### 8.2 実証（`examples/verify_reference.R`）

推論のままにせず、**Adam の最良点から BFGS を出発させた。**

```
出発点からの最大移動: 0.001424
対数尤度の改善:       0.000277
→ その場に留まった
```

**Adam の着地点は BFGS にとっても停留点。**
**遠方から出発した BFGS が届かなかっただけだと確定した。**

### 8.3 判定規則を改める

この track は一貫して「BFGS 解と一致するか」で判定してきた。
同じ尤度を別の方法で最大化しているのだから一致すべき、という理屈は正しい。
**ただし BFGS が最大点に着いていれば、の話だった。**

**改訂版:**

| `logL 差`（参照解 − Adam） | 読み方 |
|---|---|
| **正** | Adam が届いていない。**従来どおり** |
| **≈ 0** | 一致。両方が同じ点にいる |
| **負** | **参照解のほうが間違っている。** `examples/verify_reference.R` で確認する |

**距離/SE は3度目の失格。** この実行では 0.05〜10.03 とばらついたが、
`H` を**誤った参照解の位置**で評価しているので意味を持たない。

### 8.4 間引きの検証 — 決着（この実験の本来の目的）

**`rate` 1.0 → 0.1 で着地点が変わらない。**

- 対数尤度の幅は **0.17**（−91.153 〜 −91.323）
- 係数の幅は `dens_0` 0.06 / `conn_0` 0.12 / `conn_agri` 0.10。
  **いずれも標準誤差（0.2〜1.7）よりはるかに小さい**
- **1反復で使う個体は 201 → 36（5.6分の1）**

**5条件が互いに一致し、かつ全部が BFGS より高い。** この相互一致自体が、
そこが本当の最大点であることの証拠になっている。

**`s010`（`beta2` 0.8 / `rate` 0.1）も同じ場所に着いた。**
「記憶を短くするとノイズを拾う」下端が `rate < 1` で上がるかを見る条件だったが、
**0.8 では上がらなかった。** 下端の再測は `beta2` 0.5 側で行う必要がある（未実施）。
